# Dead ends

Approaches tried and dropped, with the numbers. Read before starting perf or layout work. Add a line when you drop one: date, branch, one sentence on what, one on why, where the patch or probe lives. Retry only with a specific reason the shortcoming no longer applies.

- 2026-09-27, annotation-anchor: CSS anchor positioning for the callouts instead of the measuring script. Layout cost 25 to 50% more than main on resize and page turn; only dropping the insets that place the callouts got back to main. An `anchor-name` inside a sheet also stops Blink treating the section as a layout boundary. Patch in the session scratchpad, annotation-anchor/wip-on-4c6b362c.patch.
- 2026-09-27, led-pulse-paint: moving the demo LED pulse to compositor-only properties. It already animates opacity alone and costs 0 style, layout or paint passes in isolation; the audit's LED figure was the dog-ear before #182. Nothing to change.
- 2026-09-27, css-contain: `contain` on the page's small boxes (title blocks, transport deck, sheet content and aside, post-its, callout labels and cards, profile, career, elevation, bill of materials, tech icons, theme picker, folios, open source rows, demo islands and panels). Each one gives its box a paint layer of its own, and at fractional offsets that moves text and lines by a pixel at one width or another (390, 900, 1216, 1300); the few that stay pixel-identical measure nothing. Probes in the session scratchpad, css-contain/probe (ab.mjs, gesture.mjs).
- 2026-09-27, css-contain: `contain: layout size` on each page of a stack (the `article > div` wrappers). Pixel-identical in all four themes at 1440 and 390, with and without script, but a grid item is never a layout boundary in Blink, and resize steps with a demo in view came out 1 to 2% slower in four in-page A/B runs. Adding `paint` clips the turning flap, which is a child of that box. Same probes.
- 2026-09-27, sheet-vars-css: registering `--sheet-inline`/`--sheet-block` with `@property` as lengths, or registering one non-inherited length on the frame and handing it down. Either way the frame resolves new pixels at each resize step and every element under it restyles to inherit them: 50 to 65 ms more style per step without script, against about 6 ms for the unregistered expression. Probe: session scratchpad, sheet-vars-css/quick.mjs, builds dist-var-a (registered) and dist-var-c (non-inherited).
